## 二、真正的差距

### A 类：主题自带，只是没建页面（成本最低）

这几项主题的 `page.pug` 里**已经有现成模板**，只要建一个页面文件 + 可选的数据文件。

#### A1. `/essay/` 说说 —— 短内容流

- **是什么**：不需要写成完整文章的碎片记录，像微博/朋友圈那样一条条往下排，
  用 `source/_data/essay.yml` 维护
- **成本**：低。建页面 + 维护一个 yml
- **我的判断**：**推荐**。本站现在只有 3 篇长文，说说能让站点看起来是活的，
  而且写一条的成本远低于写一篇文章

#### A2. `/equipment/` 装备 —— 好物清单

- **是什么**：分类罗列在用的设备/软件，带名称和一句话说明，用 `_data/equipment.yml`
- **成本**：低
- **我的判断**：**看你有没有想写的**。技术博客放这个挺自然（键盘、编辑器、终端、常用工具），
  但需要真实内容，我不想编

#### A3. `/room/` 小房间 —— 纯 CSS 的 3D 场景

- **是什么**：主题自带的一个纯 CSS 房间动画，**不需要任何数据文件**，建个页面就有
- **成本**：极低（一个页面文件）
- **我的判断**：**纯趣味**，和「关于」页气质的站很搭。做不做都行

#### A4. `/fcircle/` 朋友圈 —— 友链动态聚合

- **是什么**：抓取友链站点的最近文章，聚合成一条时间线
- **成本**：低（建页面），但**前提是有友链**
- **我的判断**：**暂时做不了**——你的友链是空的

---

### B 类：加纯文本页（成本低）

对照站有、主题不管，但本质上就是两个静态页面。

#### B1. `/cookies/` Cookies 政策

- **成本**：低。写一段说明本站用了哪些 Cookie（评论系统的登录状态、环境音的音量偏好等）
- **我的判断**：**看你需不需要合规姿态**。本站没有广告和第三方追踪，
  严格说不是必须；但有这个页面会显得严谨

#### B2. `/copyright/` 版权协议

- **成本**：低
- **我的判断**：**可选**。文章底部已经有版权声明块（`post_copyright`），
  单独做一个页面主要是放「转载规范」这类更长的说明

---

### C 类：主题没有，要自己做（成本中到高）

**这一类的重点：对照站的 `charts`、`air-conditioner`、`tools` 在主题源码里根本不存在，
是站主自己写的。** 我做的话也要从零写。

#### C1. `/charts/` 统计

- **对照站是什么**：用 ECharts 画的图表 + 一个标签云（「兴趣点」）
- **成本**：中。要引入 ECharts、写一个页面模板、把 Hexo 的文章数据喂进去
- **我的判断**：**价值一般**。侧栏已经有「网站资讯」显示文章数/字数/访客数，
  图表能好看，但本站目前只有 3 篇文章——**数据太少，图会很空**。
  建议等文章多起来再做

#### C2. `/air-conditioner/` 小空调

- **对照站是什么**：一个能调温度、开关的拟物空调面板，纯前端玩具
- **成本**：中。要自己写 HTML/CSS/JS
- **我的判断**：**不推荐**。纯粹的装饰性玩具，和你站「安静、朴实」的调性不太搭。
  真想要趣味页，主题自带的 `/room/` 更省事

#### C3. `/tools/` 工具库

- **对照站是什么**：一个很长的外链合集（200+ KB 的页面），分类罗列常用在线工具
- **成本**：中。页面本身好写，**难在内容**——要整理出几十条真正有用的链接
- **我的判断**：**取决于你**。这是内容型工作不是技术型工作。
  如果你平时收藏了不少工具，值得做；没有的话硬凑会很难看

## 三、我建议的顺序

如果只做三件，我建议：

1. **A1 说说页** —— 成本最低、对「站点看起来是活的」帮助最大
2. **A3 小房间** —— 一个文件的事，趣味性够
3. **A2 装备页** —— 如果你确实有想写的设备/软件

**C 类我建议都先放着**：`charts` 数据太少，`air-conditioner` 和站点调性不搭，
`tools` 等你真有内容再说。
